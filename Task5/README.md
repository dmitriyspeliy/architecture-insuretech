# Задание 5. Проектирование GraphQL API client-info

В рамках задания REST API сервиса `client-info` переведён в GraphQL-схему.

Исходный REST API содержит отдельные ресурсы для получения карточки клиента, документов и родственников:

- `GET /clients/{id}` — получение основной информации о клиенте;
- `GET /clients/{id}/documents` — получение документов клиента;
- `GET /clients/{id}/relatives` — получение родственников клиента.

Проблема REST-подхода в данном сценарии заключается в том, что потребители часто запрашивают разные наборы данных. При большом количестве атрибутов карточки клиента единый REST-ресурс возвращал бы слишком большой payload, а множество мелких REST-ресурсов увеличивает количество сетевых вызовов и RPS сервиса `client-info`.

GraphQL-схема позволяет потребителю самостоятельно выбрать только нужные поля и связанные объекты. Например, в одном запросе можно получить имя клиента, номера документов и список родственников, не запрашивая всю карточку клиента целиком.

Основной файл схемы:

```text
client-info-schema.graphql
```

## Основные сущности

- `Client` — клиент;
- `Document` — документ клиента;
- `Relative` — родственник клиента.

## Основные queries

- `client(id: ID!): Client` — получение карточки клиента с возможностью выбора вложенных данных;
- `clientDocuments(clientId: ID!): [Document!]!` — получение документов клиента;
- `clientRelatives(clientId: ID!): [Relative!]!` — получение родственников клиента.

Отдельные queries `clientDocuments` и `clientRelatives` оставлены для покрытия существующих REST-операций. При этом основной сценарий использования GraphQL — запрос через `client`, где потребитель сам выбирает необходимые поля и вложенные коллекции.

## Пример запроса

```graphql
query GetClientForInsuranceSale($clientId: ID!) {
  client(id: $clientId) {
    id
    name
    documents {
      type
      number
      expiryDate
    }
    relatives {
      relationType
      name
    }
  }
}
```
